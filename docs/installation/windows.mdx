# Windows

import useBaseUrl from '@docusaurus/useBaseUrl';
import ReverseProxy from '/snippets/reverse-proxy.mdx';

There are two ways to run autobrr on Windows:

- **[Desktop app](#desktop-app)**: an installer that runs autobrr in the background with an icon in the system tray. It starts when you log in, updates itself, and needs no admin rights. Pick this one unless you need autobrr running while nobody is logged in.
- **[Background task](#background-task)**: the plain `autobrr.exe` started by Task Scheduler, which can run without anyone logged in.

## Desktop app {/* #desktop-app */}

### Install {/* #desktop-install */}

Download `autobrr-desktop_<version>_windows_x86_64.msi` from the [latest release](https://github.com/autobrr/autobrr/releases/latest) and run it. It installs autobrr for your Windows user in `%LOCALAPPDATA%\Programs\autobrr`, adds **autobrr** to the Start menu and starts it. No admin rights are needed and there is no setup wizard.

The release also has `autobrr-desktop_<version>_windows_x86_64.zip` with the same `autobrr-desktop.exe` if you would rather unpack it into a folder of your choice.

:::caution[Windows SmartScreen]
The installer and exe are not code-signed yet, so Windows SmartScreen may warn that it protected your PC. Click **More info**, then **Run anyway**.
:::

Once it runs, open the web UI from the tray icon and create your user.

### Tray menu {/* #desktop-tray-menu */}

Right-click the autobrr icon in the system tray:

- **Open Web UI**: opens autobrr in your browser, once it has started.
- **Open Config Folder**: opens the folder with `config.toml`, the database and the logs.
- **Start on login**: starts autobrr when you log in to Windows. It shows up under **Settings > Apps > Startup** and can be turned off there too.
- **Check for updates**, **Install update**, **Install updates automatically**: see [Updates](#desktop-updates).
- **Quit**: shuts autobrr down cleanly.

Logging off or shutting down Windows also shuts autobrr down cleanly.

### Files and logs {/* #desktop-files */}

The desktop app keeps its config, database and logs in `%APPDATA%\autobrr`:

- `config.toml`, see [configuring autobrr](../configuration/autobrr.mdx)
- `autobrr.db`
- `logs\autobrr.log`, since there is no console window to log to. A `logPath` set in `config.toml` takes precedence.

If autobrr fails to start, for example because port 7474 is already in use, it shows an error dialog with the reason and the path to the log file.

Only one copy of autobrr runs per config folder. Starting it again shows a message that it is already running.

### Move an existing install {/* #desktop-move-existing */}

To switch from the plain `autobrr.exe` to the desktop app and keep your setup:

1. Stop the old autobrr, including its Task Scheduler task, and disable that task so the two don't fight over the port and database.
2. Copy `config.toml` and `autobrr.db` from your old autobrr folder into `%APPDATA%\autobrr`. **Open Config Folder** in the tray takes you there.
3. Quit autobrr from the tray and start it again from the Start menu.

### Updates {/* #desktop-updates */}

With `checkForUpdates` on in `config.toml` (the default), autobrr checks for new releases at startup and every two hours, and shows a notification when one is out. **Check for updates** checks right away either way.

- **Install update vX.Y.Z** asks for confirmation, downloads the release, checks it against the release checksums and restarts autobrr on the new version. The previous version is kept as `autobrr-desktop.exe.old` next to the exe.
- **Install updates automatically** does the same without asking, for releases that have been out for at least 24 hours. It is off by default, and does nothing when `checkForUpdates` is off.

autobrr can only update itself when its folder is writable by your user. The installer's folder always is. If you unpacked the zip into a folder like `C:\Program Files`, install updates by downloading the new release yourself.

### Uninstall {/* #desktop-uninstall */}

Uninstall **autobrr** from **Settings > Apps**. This removes the program and its start on login entry, but keeps `%APPDATA%\autobrr`, so your config and database stay. Delete that folder as well to remove everything.

## Background task {/* #background-task */}

In this setup we will create a Windows task that runs `autobrr.exe` in the background. This way we won't need to have a command prompt window open 24/7.

### Download package {/* #download-package */}

Download the latest Windows release and unpack. Place everything in `C:\autobrr` or some other directory.

Latest release can always be found at [Github](https://github.com/autobrr/autobrr/releases/latest).

#### Manually configure autobrr (optional) {/* #manually-configure-autobrr */}

You can either let autobrr create the config itself at startup, or create one manually. For more information, please visit [configuring autobrr](../configuration/autobrr.mdx) which covers creating a user manually, configuring the default port, setting the desired log level, etc.

### Create Windows task {/* #create-windows-task */}

Press your Windows key and search for **Task Scheduler** and lets **Create basic task**.

<img src={useBaseUrl('/img/a.%20create%20basic%20task.png')} />

Add a name, this will show up in the Task Scheduler. Feel free to add the autobrr description if you'd like:

> autobrr monitors IRC announce channels to get releases as soon as they are available with good filtering.

<img src={useBaseUrl('/img/b.%20name%20task.png')} />

Next you'll set a **Trigger** which we want to start as soon as we **login to the computer**.

<img src={useBaseUrl('/img/c.%20trigger.png')} />

Our Action will be to **Start a Program** and we'll set our path to the autobrr.exe. Just click **Browse** and navigate to where you put your **autobrr.exe**

:::caution[Don't skip "Start in"]
Set **Start in (optional)** to the folder autobrr lives in, e.g. `C:\autobrr`. It is not actually optional for autobrr: without it, Windows starts the task in `C:\Windows\System32`, and autobrr creates and reads its `config.toml` and database **there** instead of in your autobrr folder. This is the most common cause of autobrr "losing" its settings or asking you to register again after a reboot.

Alternatively, put `--config C:\autobrr` in **Add arguments (optional)**, which points autobrr at the right folder no matter where the task starts.
:::

<img src={useBaseUrl('/img/d.%20action.png')} />

<img src={useBaseUrl('/img/task_action.png')} />

Our final step is to **Run whether user is logged on or not** After you set this it'll prompt you for the Windows Administrator password. Enter it and you should be ready to run.

<img src={useBaseUrl('/img/f.%20properties.png')} />

And we're done, the scheduled task has been created (you'll find it in Task Scheduler, not in the Windows Services list). Now right click on autobrr in the list and click **Run.**

<img src={useBaseUrl('/img/g.%20service%20created.png')} />

:::tip

If you ever need to restart the service, within Task Scheduler you can click on End and Run on the right side bar.

:::

## Finishing up {/* #finishing-up */}

Now that autobrr is up and running, you should be able to visit your web UI at [http://localhost:7474](http://localhost:7474), `http://YOUR_LOCAL_IP:7474` or `http://domain.tld:7474` and proceed with your registration/login.

:::info
If the web UI asks you to register again after a restart, or your settings seem to be gone, the task is almost certainly running without **Start in** set; see [the caution above](#create-windows-task).
:::
